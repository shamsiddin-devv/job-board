# WorkUZ on Render Free

Use a free Render Web Service for NestJS, a free Render Key Value instance for short-lived OTP records, and a Neon Free project for PostgreSQL. Render's own free PostgreSQL databases expire after 30 days. The web service sleeps after 15 minutes without inbound traffic. An incoming request wakes it, which can take around a minute. Use this for a small public launch with that availability tradeoff. [Render free limits](https://render.com/docs/free)

1. Sign in to [Render](https://dashboard.render.com/) and connect the GitHub repository or an authorized fork containing the reviewed WorkUZ code and `render.yaml`. Deploy the Blueprint from that branch. Both services should show the Free plan. The Redis URL stays on Render's private network. Render provides an HTTPS `onrender.com` URL. [Render Blueprint setup](https://render.com/docs/infrastructure-as-code)
2. Create a Neon Free project near Frankfurt. Enter the pooled connection URL as `DATABASE_URL` and the direct URL as `DIRECT_DATABASE_URL` in the Render dashboard. Keep the provider's TLS options. The start command applies Prisma migrations through the direct connection before accepting requests. For an existing production database, follow the baselining instructions in the main README before the first start.
3. Configure a Brevo Free sender. Use the verified sender address as `SMTP_EMAIL`, Brevo's SMTP login as `SMTP_USER`, and the generated SMTP key as `SMTP_PASS`. The Blueprint uses Brevo's TLS port 2525 because Render blocks outbound ports 25, 465, and 587 on free services. Brevo can rewrite the sender when using a personal email address. Verify actual OTP delivery to a test inbox. [Brevo SMTP ports](https://help.brevo.com/hc/en-us/articles/10905415650322-Which-SMTP-port-should-I-use-Port-587-465-or-2525)
4. Fill in Cloudinary and OAuth settings in the dashboard. Register the exact URLs at the providers after confirming the Render hostname, for example `https://workuz-api.onrender.com/api/auth/google/callback` and `https://workuz-api.onrender.com/api/auth/github/callback`. The start command defaults `FRONTEND_URL` to the Render API origin. Set the actual HTTPS frontend origin once available. The browser cookie and OAuth flow need a same-site frontend.
5. Wait for a successful deployment and verify `/api/health/live` and `/api/health/ready` return HTTP 200. Then verify an OTP registration and a file upload. Credentials belong in the provider dashboards and Render secret variables.
